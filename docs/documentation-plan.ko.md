# 문서 계획

이 문서는 어떤 정보를 어디에 적는지, 어떻게 최신으로 유지하는지, 무엇으로
검사하는지를 정의한다. 이 저장소에 적용된다.

## 문제

이 저장소의 문서는 코드가 더 이상 갖지 않는 동작을 서술한다. `README.md`는
Compose 파일로 대체된 `stack.yaml` 형식을 설명한다. `GUIDE.md`는 현재 머신
단위인 도메인을 프로젝트 단위로 설명한다. 두 문서 모두 동작이 바뀐 뒤 검증되지
않았다.

사용법도 독자에게 도달하지 않는다. 바이너리만 설치한 프로젝트는 이 저장소의
문서를 받지 않으므로, 그 프로젝트에서 작업하는 에이전트는 문서를 읽을 수 없다.

## 규칙

1. 문서는 현재 동작을 서술한다. 방향이 바뀌면 명세를 먼저 수정하고, 구현되지
   않은 부분을 표시한다.
2. 동작을 바꾸는 변경은 같은 변경에서 명세, `docs/features.md`,
   `CHANGELOG.md`를 함께 수정한다.
3. 영어 문서가 정본이다. 독자용 문서마다 `<이름>.ko.md` 한국어 문서를 둔다. 두
   파일은 함께 수정하고 같은 정보를 담는다.
4. 테스트 결과와 배포 결과를 따로 기록한다. 이전 결과를 변경된 코드의 검증
   근거로 사용하지 않는다.
5. `make docs-check`를 기본 검사에 포함한다. 링크, 한국어 문서 존재, 상태 항목을
   검사한다. 내용의 정확성은 코드와 테스트를 읽어 확인한다.
6. 문서, 주석, 커밋 메시지는 이 프로젝트만 서술한다. 외부 프로젝트를 언급하지
   않고 참고 대상을 밝히지 않는다.
7. 주석, 커밋 메시지, 문서는 직접적인 표현을 쓴다. 동작을 이름으로 부르고,
   주체와 대상을 밝히고, 원인은 한 문장으로 적는다.

## 배치

| 위치 | 내용 |
| --- | --- |
| `README.md` | 프로젝트 소개, 최소 시작 절차, 나머지 문서 링크 |
| `docs/spec/` | 승인된 구조, 계약, 규칙, 인수 기준 |
| `docs/features.md` | 기능별 구현 상태, 검증 근거, 배포 상태 |
| `docs/operations/` | 현재 유효한 설치, 실행, 검증 절차 |
| `CHANGELOG.md` | 기능 변경과 검증 결과 |
| `docs/plans/` | 승인 대기 제안. 승인 후 명세에 반영하고 삭제 |
| `AGENTS.md` | 이 저장소의 개발 절차와 필수 검사 |

`AGENTS.md`는 이 저장소를 개발할 때 읽는 문서다. 다른 프로젝트를 위한 사용
계약이 아니다.

## 사용법은 명령이 담는다

`containerctl`을 설치한 프로젝트는 바이너리를 받고 이 저장소를 받지 않는다.
따라서 사용법은 명령에 담는다.

| 명령 | 출력 |
| --- | --- |
| `containerctl brief` | 한 화면짜리 사용 계약: 목적, 명령, Compose 스키마, 불변식, 진단. `--json` 지원 |
| `containerctl schema` | Compose 확장 계약: `x-containerctl` 키, `containerctl.*` 라벨, 포트 결정 순서. `--json` 지원 |
| `containerctl help <명령>` | 명령이 하는 일, 머신에 바꾸는 것, 관리자 권한 필요 여부, 예시 |
| `containerctl status --json` | 현재 머신 상태 |

`brief`와 `schema`는 코드가 사용하는 선언에서 생성하므로 구현과 어긋날 수 없다.

## 파일

### 명세, `docs/spec/`

| 파일 | 내용 |
| --- | --- |
| `architecture.md` | 구성 요소, 요청 경로, 라우팅 상태의 소유 |
| `cli.md` | 명령 계약: 인자, 효과, 종료 동작, 권한 요구 |
| `compose-schema.md` | `x-containerctl` 키, `containerctl.*` 라벨, 기본값, 검증 규칙 |
| `machine-state.md` | 저장소 밖에 생성되는 파일과 시스템 상태, 각각의 제거 방법 |
| `peers.md` | 다른 기계의 도메인에 닿기: 신원, 공개하는 것, 받아들이는 것 |

### 운영, `docs/operations/`

| 파일 | 내용 |
| --- | --- |
| `install.md` | 1회 머신 설정과 그것이 바꾸는 것 |
| `using.md` | 프로젝트 추가, 실행, 일상 명령 |
| `troubleshooting.md` | 증상, 원인, 진단 명령 |

### 상태

`docs/features.md`는 기능마다 한 행을 갖는다: 구현 상태, 검증 근거, 빌드된
바이너리에 포함되었는지 여부.

`CHANGELOG.md`는 날짜별 항목으로 동작 변경과 각 변경에 대해 실행한 검증을
기록한다.

## 검사

`make docs-check`가 검사하는 것:

- `README.md`, `AGENTS.md`, `CHANGELOG.md`, `docs/`의 모든 Markdown 링크가
  존재하는 파일을 가리키는지;
- 독자용 문서마다 `.ko.md` 문서가 있고 제목 개수가 같은지;
- `docs/features.md`의 모든 행에 상태와 근거 칸이 있는지;
- `containerctl brief`와 `containerctl schema`가 실행되어 출력을 내는지.

`make check`는 `gofmt`, `go vet`, `go test`, `docs-check`를 실행한다.
